# Voyd Orbit

Voyd Orbit is a full-stack orbital mechanics sandbox and a deliberately
ambitious Voyd example. Build systems of stars, planets, moons, asteroids, and
black holes; drag them through space, throw new bodies into orbit, inspect and
edit their physical properties, and save the result to the server.

Every piece of application logic is Voyd: the browser state machine, fixed-step
physics, Canvas renderer, interactions, HTTP client, shared JSON codec,
validation, REST router, server, and filesystem repository. The small `.mjs`
files are build and generic Wasm/VX host glue; HTML metadata, CSS, and the SVG
icon are static presentation assets.

## Run it

Install the monorepo dependencies from the repository root, then start the
example:

```sh
npm install
cd examples/voyd-orbit
npm run dev
```

Open [http://127.0.0.1:3000](http://127.0.0.1:3000). The first build compiles
separate Voyd programs for the browser and server. `VOYD_WEB_PORT` and
`VOYD_WEB_HOST` override the default bind address.

Useful commands:

```sh
npm test       # focused Voyd physics, codec, repository, and REST tests
npm run build  # optimized browser bundle plus server/client compile checks
npm start      # run a production build after `npm run build`
```

## Experience

- Pan by dragging empty space and zoom around the cursor with the wheel.
- Click a body to select it, drag to reposition it, or edit exact values in the
  inspector.
- Choose a body from the left palette, click to place it, and drag to set its
  initial velocity.
- Explore six built-in systems: a stable planetary system, binary stars,
  three-body chaos, a gravity assist, an asteroid belt, and a black-hole flyby.
- Use `Space` to pause, `R` to reset, `F` to follow the selection, `Delete` to
  remove it, and `+` / `-` to change time speed.

The physics engine uses velocity Verlet integration with explicit AU, solar-mass,
and day units. A fixed timestep keeps simulation behavior independent of display
frame rate, and gravitational softening handles close approaches without
singular accelerations. The direct O(n²) force calculation comfortably covers
the intended hundred-body scale.

## Architecture

```text
src/
├── shared/       package root plus data model, JSON codecs, validation, safe IDs
├── simulation/   package root plus vectors, scenarios, gravity, integration
├── client/       browser package root, state, Canvas scene, VX controls, API
├── server/       package root, REST routes, atomic filesystem repository
└── main.voyd     server and server-rendered page entrypoint
```

Each domain folder contains a `pkg.voyd` that defines its exported surface.
Imports use the logical paths `src::shared`, `src::simulation`, `src::client`,
and `src::server`; the physical `pkg` filename never appears in source imports.
The browser compiler uses `client/pkg.voyd` as its program entrypoint.

The browser and server compile the same shared types and codecs. The simulation
engine has no rendering dependency. Saved documents use schema `version: 1` and
live as readable JSON in `data/simulations/<id>.json`. IDs are generated by the
server and validated before path construction. New saves use exclusive creation;
replacements use an atomic same-directory temporary-file write. A malformed save
is skipped during listing so it cannot make the rest of the library unavailable.

The scene renderer projects simulation state into VX's typed Canvas API. It
uses logical CSS-pixel coordinates while the browser host owns high-DPI backing
store scaling. Trails, bodies, transformed path-based velocity arrows, dashed
title accents, compositing, and text are ordinary Voyd draw values collected
into a version-2 frame; the browser host remains compatible with legacy
version-1 primitives. VX derives the Canvas MessagePack schema from typed wire
records, so Orbit does not repeat host field names or build boundary maps. The
title is measured through an explicit
`canvas::measure_text` command and the result is stored in the model before the
next frame. Canvas pointer-down events request pointer capture, so panning,
body dragging, and velocity placement keep receiving moves and the final
release outside the canvas. The model tracks the active pointer ID, ignores
other pointers, and abandons the matching interaction on cancellation.

The backend is deliberately mundane. Its value is precisely that routing,
structured errors, validation, JSON, random IDs, time, and safe persistence do
not need an escape hatch: the same language carries the application from the
browser canvas to the server filesystem.
